# Follow-ups

Review findings deferred under the stopping rule (`CODE_REVIEW.md`), and cleanups too broad for the change that found them. Each entry names where, the scenario, and the suggested fix. Remove an entry in the change that resolves it.

## `@obs/kafka`
- **[major, deferred by the user 2026-10-21] `commit()` does not report broker-side failures** (`packages/kafka/src/confluent.ts` `commit`, `native-augment.ts`): the binding's `commitCb` calls librdkafka `commitAsync`, so its callback means "queued", not "stored". A commit rejected during a rebalance, from a non-member, or while the broker is down resolves anyway, contrary to the port's "rejects on failure". Impact in this design: more replay after a restart (the aggregator restores from its ES checkpoint; sinks are idempotent), not wrong data. Agreed fix: after queuing, read back `committed()` and reject unless it matches; contract case first (a commit from a non-member of an active group rejects; reproduces on a real broker); make the fake reject that case; correct the comments that claim commitCb waits for the broker. Do this before `BaseConsumer`.
- **Fake skips `onAssigned([])`/`onRevoked` for a member with no partitions** (`memory.ts`, pinned by two `memory.test.ts` cases): the real adapter calls `onAssigned([])` when a group has more members than partitions. Fix: call the listener with `[]` in the fake and move the case into the contract suite.
- **Test support has no package export** (`packages/kafka/package.json`): services cannot import `startKafka` or the contract helpers for their own Testcontainers tests. Fix: add a `./testing` export when the first service needs it.
- **`eventually` has no wall-clock budget** (`packages/kafka/src/testing/contract.ts`): steps that poll two members at 1 s each can outlast the 60 s integration `testTimeout`, so a stuck wait reports a Vitest timeout instead of "gave up waiting for ...". Fix: give `eventually` a deadline as well as an attempt cap.
- **Contract tests and `startOnce` do not clean up on failure** (`contract.ts`, `testing/kafka-container.ts`): a failing assertion leaves native clients connected (they log errors after `kafka.stop()`, adding noise to the `afterAll` error check), and a failed admin connect leaves the started container running before the retry. Fix: `try/finally` or `onTestFinished` for disconnects; stop the container when admin setup fails.
- **`Clock`/`FakeClock` live in `@obs/kafka`** (`packages/kafka/src/clock.ts`): Phase 3 domain classes (the watermark idle rule) need an injected clock but must not import Kafka. Fix: move it to a Kafka-free package before Phase 3.
- **`offsetsForTimes` accepts negative timestamps** (`confluent.ts`, `memory.ts`): Kafka reads -1/-2 as latest/earliest sentinels, so the adapters diverge; callers pass epoch ms, so it is unreachable today. Fix: reject negative or non-finite timestamps in both adapters.

## Cross-package
- **`dist` contains compiled tests** (every `packages/*/tsconfig.json`): `*.test.js` and test support are emitted next to the runtime code. Harmless (the `exports` map points only at `dist/index.js`), but noise in images. Fix: a build tsconfig that excludes tests, applied to all packages at once.
